# 本轮边界与下一阶段

## 当前模拟实现

| 能力 | 本轮实现 |
|---|---|
| 行情和事件 | 固定版本的虚构证据样本，不访问外部数据源 |
| 研究 Agent | 确定性 Python 输出，明确带 `[模拟]` 标记 |
| 反方 Agent | 读取研究输出与同一证据包，提出固定的证据缺口 |
| 协调与合并 | 真实 LangGraph 状态图，结论内容为模拟流程产物 |
| 模型适配 | `ModelAdapter` 协议及本地模拟实现，无 API Key、无模型费用 |
| 故障场景 | `fail_once` 在第一次反方执行失败；`timeout` 每次模拟反方超时 |
| 模型成本 | 数据结构有 token / cost 字段，当前返回 null，未伪造调用费用 |
| 证券与周期 | 请求元数据和格式校验；没有预测或实际行情匹配 |

数据库事务、Redis 通知、后台 Worker、状态查询、重试、审计记录和浏览器交互是真实运行的软件组件。

## 预留但未实现

候选发现、真实技术指标、波段策略、持仓和交易记录业务、全市场扫描、真实模型、评测器与数据集、RSI 实验执行均未实现。对应逻辑目录或数据库记录结构仅定义职责边界。本轮没有自动策略优化、代码修改、配置晋级、真实账户或交易接口。

## 当前限制与风险

- 本机单用户应用，没有认证、授权、限流、用户隔离或公网部署加固；默认仅监听 loopback。
- 固定模拟样本只能证明流程与结构，不能证明任何策略收益、指标阈值或 Multi-Agent 优势。
- Redis 可降级，PostgreSQL 是必需依赖；未提供数据库高可用、备份计划与生产灾备验证。
- 租约回收会重新执行整个图，保留旧 attempt；没有 LangGraph 节点级续跑。未来真实模型调用可能重复计费，需要单独设计外部调用语义。
- `/readyz` 验证 API 能访问数据库与 Redis，不证明 Worker 活跃；生产使用前应补 Worker 心跳、积压指标和告警。
- `GET /api/tasks` 限制最近 50 条，尚未提供分页、归档、数据保留策略和全文检索。
- 模型超时通过可取消的模拟适配器验证；真实供应商的网络、限流、协议差异和费用记账尚未验证。
- RSI 表仅预留记录，不代表完整批准权限系统；未来必须设计不可绕过的独立评测、人工批准与回滚程序。

## 下一阶段建议（本轮不自动执行）

1. 先定义研究样本与验收标准：A 股交易日历、1–5 日研究窗口、证据时点、事件窗口、停复牌/涨跌停等边界；明确禁止未来数据泄漏。
2. 选择一个合法可用的数据源，完善来源、获取时间、市场时间、修订版本和数据质量检查，仍保持模拟数据与真实数据显式隔离。
3. 接入一个真实模型适配器，加入超时、有限重试、结构化输出校验、token/费用与证据引用校验，保留无 Key 模拟模式。
4. 建立独立离线测试集，比较单 Agent 与多 Agent 的可复核性、错误率、成本和稳定性，再决定是否增加角色；不预设多 Agent 更好。
5. 持仓监控、人工决策记录与 RSI 各自单独设计。RSI 候选仅在隔离实验中运行，评测通过并经人工批准后，才讨论受控发布与回滚。
